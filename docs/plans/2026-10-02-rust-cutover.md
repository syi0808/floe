## Decisions fixed for the target

- Keep existing owner crates. App composes owners, admits host identity, and owns host lifetime; it does not implement owner policy or workflow state machines.
- Conversation owns Run/Session admission, durable interaction origin and continuation. Experts owns package installation, binding, Task admission and settlement. Runtime owns the one role-neutral execution loop. Shipped Experts use the same package and runtime path as additional installed packages.
- Connections owns Gateway pairing, verified authority enrollment, credential installation completion and integration lifecycle. Secrets remain within provider/platform adapters. Inference sees prepared model transport, never endpoint/bearer/polling proof.
- Access owns source read and processing authority. Replace recipient-specific model consent by category-bounded `DeviceOnly` / `GatewayAllowed` source policy. An ordinary reasoning call is not a consent request. Health requires a separate source-owned local privacy transform; it remains `HighlySensitive` and transform success does not grant processing authority.
- Gateway Primary is selected before projection and dispatch. Local fallback is allowed only for an explicitly valid planning-time Primary absence. Credential error, foreign identity, malformed discovery, source denial, timeout, or failure after Primary selection must not activate fallback.
- Preserve durable pre-dispatch intent, exact source/grant authority, physical resources, CAS, host generation and person/device binding, provenance, cancellation direction, uncertain external-write recovery and usage charging.

## New boundary contracts

These signatures specify the target interfaces, not code to install during planning. `BoxFuture` is the existing boxed Send future convention. IDs are validated non-nil newtypes, not secret handles that can be forged by serialized UI input. Domain methods re-read admitted host identity rather than accepting caller-asserted identity as authority.

### Inference planning observation

At `crates/modules/inference/src/ports/model_provider.rs`:

- `ModelProvider::observe_primary<'a>(&'a self, request: &'a ModelPlanRequest, scope: &'a ExecutionScope) -> BoxFuture<'a, Result<PrimaryObservation<Self::Prepared>, ModelObservationError>>`.
- `ModelProvider::observe_local_fallback<'a>(&'a self, request: &'a ModelPlanRequest, scope: &'a ExecutionScope) -> BoxFuture<'a, Result<LocalObservation<Self::Prepared>, ModelObservationError>>`.
- `PrimaryObservation<P> = Available(PreparedModelProfile<P>) | Absent(PrimaryAbsence)`; absence variants are `NoGatewayConfigured`, `PurposeNotConfigured`, `PurposeDisabled`. This is a closed set: no `PurposeUnavailable` catch-all and no failure/empty-vector conversion to absence. Exact authenticated inventory and error mapping is specified in [canonical contracts](2026-10-02-canonical-contracts.md).
- `LocalObservation<P> = Available(PreparedModelProfile<P>) | Unavailable(LocalAvailabilityReason)`.
- `ModelObservationError = InvalidIdentity | InvalidInventory | CredentialRejected | PermissionDenied | Timeout | TransportUnavailable | Cancelled | StorageUnavailable | QuotaExceeded`. None converts to PrimaryAbsence.
- `ModelPlanRequest` carries purpose, consumer, requested capability set and admitted non-secret principal/device identity; no connection credential, route URL, recipient-consent flag, source content or prompt.
- `PreparedModelTransport::generate(request: CanonicalModelRequest, target: AdmittedDispatchTarget)` retains its Result/future shape; target proves the selected Device/Gateway capability, not approval of an exact downstream model recipient.

Inference validates the complete observation, selects one route, records its non-secret plan identity, then obtains the processing projection for that route. Primary absence is not a blanket permission to process a source locally: all source admission remains in force. A selected Primary never falls back after error; a correction for malformed model output, where supported, remains a bounded same-plan attempt and never changes provider. All roles use the same purpose/consumer-bound planner and Engine call path.

### Prepared model plan survives projection

The planning seam belongs to the agent contract, so Runtime depends only on `floe-agent-contract`, never Inference. Add `crates/contracts/agent/src/model_plan.rs`, exported from `lib.rs`, and replace `ModelPort::generate` at `ports.rs:191` with:

```rust
pub trait ModelPort: Sync {
    fn prepare<'a>(
        &'a self,
        request: ModelPlanRequest,
        scope: &'a ExecutionScope,
    ) -> BoxFuture<'a, Result<Box<dyn PreparedModelCall>, AgentFailure>>;
}
pub trait PreparedModelCall: Send + Sync {
    fn plan(&self) -> &PreparedModelPlan;
    fn generate<'a>(
        &'a self,
        request: ModelRequest,
        scope: &'a ExecutionScope,
    ) -> BoxFuture<'a, Result<ModelResponse, AgentFailure>>;
}
```

The returned object owns its prepared transport (including any private adapter capability through an owned/Arc handle); it does not borrow an Inference service or use a process-global plan-ID lookup. It is not serializable or cloneable through this contract. `ModelPlanRequest` has admitted principal/device, purpose/consumer, required capabilities. No source text or prompt is needed to select the processing boundary. `PreparedModelPlan` has a fresh plan operation ID, principal/device, purpose/consumer, effective capabilities, `ProcessingBoundary`, and an opaque non-secret authority-binding digest. The digest binds selected Gateway identity/generation or exact device transport identity; it is correlation/recovery evidence, never bearer authority. Credentials, endpoint, downstream provider/profile and Access implementation types remain absent from this contract.

`ModelProjectionRequest` includes the complete immutable `PreparedModelPlan`; `AuthorizedModelProjection` includes its plan ID and binding digest. The Inference implementation retains the actual prepared transport and verified binding privately and refuses any mismatched plan/principal/purpose/projection. Source projection uses only the plan's boundary and requirements; Access admission/consume/result fences use the identical privately held verified binding. A live binding change is an error, not a reroute. `generate` never calls selection/observation again. Bounded corrective attempts can reuse this same object, with distinct attempt/projection identities and fresh source fences; no fallback is introduced.

Engine's order is: prepare one call; mint projection operation identity; ask projection against `prepared.plan()`; on source review return without model intent; on Ready validate exact plan binding, persist ModelIntent including the non-secret plan snapshot, then invoke this object's `generate`. A source-review resume begins a new projection operation and may prepare again, but must re-read policy and cannot reuse the old review as permission for different immutable facts. On reopen, existing Working runs and unresolved model attempts remain Interrupted under the current journal recovery policy; there is no automatic model reissue or transport reconstruction. A response lost after handoff retains the unknown charge. The stored public plan supports audit and source-review identity, while an explicitly admitted linked run obtains a fresh plan and projection. No speculative expected-plan recovery field is added. This separates serializable audit identity from unpersistable secret capability without a global stash or second selector.

Callers cut over together in S1.1/S1.4/S1.5: Engine invokes prepare before project; InferenceService implements prepare and a private prepared-call object, moving selection out of generate; Context projector accepts the plan; Access receives its private verified dispatch target; Conversation journal stores the plan snapshot; package adapters and Learner use the common port and cannot impose alternate local-only selection. The provider observation request type is this same agent-contract `ModelPlanRequest`, not a duplicate Inference DTO.

`PairingStartRequest` has admitted person/device and a non-secret configured Gateway selection. `PairingChallenge` has opaque attempt ID, display code, expiry, and public producer/issuer review facts. Adapter-private staging stores polling proof, signed challenge bytes and approved bearer. `PairingObservation` contains enum state and public verified identity facts only. Connections durably owns operation ID, checked generation, state and expected reviewed identity; it re-observes before completing. `VerifiedEnrollment` binds owner key, producer identity, exact person/device/client, local confirmation and administrator approval. It is not constructible from UI reports.

`PairingError = InvalidInput | ForeignIdentity | ChangedProducer | Expired | Rejected | Conflict | CredentialUnavailable | StorageUnavailable | TransportUnavailable | Cancelled | DeadlineExceeded`. Errors are display-safe codes, never serialized raw responses or secrets. No failed call silently deletes the previous usable connection or key.

Credential commit is idempotent by pairing operation ID. It consumes adapter staging, atomically installs one exact credential record, reads it back and compares public binding/generation. Connections only persists `Paired` after verified readback. On response loss, retry queries readback and rejoins an identical committed operation; changed binding conflicts. If OS secure-store atomicity cannot span multiple slots, one serialized record in one exact slot is authoritative, with operation ID and generation inside it. Vault owner keys and producer pin remain independently validated; do not invent an atomic cross-store transaction.
