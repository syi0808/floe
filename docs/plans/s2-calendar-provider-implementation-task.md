## Authority boundary and registry

Implement `CalendarProductTransport::{observe,acquire}`. `observe` is metadata-only over the exact supplied configured SourceConnection; it reports actual OS permission/subject or signed provider identity/current generation. Context separately reloads Connections rows/fences; Access alone decides product admission/release. `acquire` receives a private `ProductCalendarDispatchFence` and returns terminal typed batches plus exact result binding. It cannot manufacture a permit, grant, source authority or assistant dependency.

Implement the real closed provider-side `ProductGatewayLeaseRegistry` state `Locked | Ready { generation, actor, credentials, signer } | Closed`. Use monotonically increasing positive local generation; retain the largest published generation even after Locked. Constructor starts Locked. App is the sole publisher/lifecycle caller. Provide `publish(generation,actor,credentials,signer)`, `lock()`, `close()` and `acquire(actor,expected_generation:Option<u64>) -> retained lease`. None means the initial observation may acquire the currently Ready generation; subsequent reads/signatures/releases pass the positive generation retained in the Access permit. `publish` rejects a closed registry and any non-increasing generation; replacement closes/cancels the old generation before publishing the new one. `lock`/`close` synchronously close admission and cancel all retained leases before Vault seal. A lease owns exact actor, generation, credential and signer handles, a cancellation fence and registry-generation verification. Locked returns VaultLocked; Closed/unavailable/mismatched generation is a typed failure. No optional whole SourceServices, new credentials, absence fallback or mutable service locator.

`ProductCalendarPermission::ProviderRead` contains both `identity_generation` (actual provider identity generation) and `gateway_runtime_generation` (local registry generation). The latter is never sent to Go as provider identity or a grant. Retain one exact Gateway lease throughout the complete source acquisition. Check its cancellation/generation and `permit.revalidate(scope)` before every page admission/read/sign/release and after response decode. Never substitute a fresh generation. All I/O is outside storage locks.

## Exact private Gateway HTTP declaration

All four routes are authenticated POST under `/v1/calendar/mirror/`. JSON decoding rejects duplicate, unknown and case-variant keys, null required fields, invalid UUID/base64/hex, excessive depth/bytes and mismatched echoes. Successful bodies are exactly these closed objects; failures retain the existing HTTP `operation.Result`/failure envelope and typed status mapping, never an empty successful page.

1. `source-preview` request: `{schema_version:1,connector_id:String,connection_id:String,local_revision:u64}`. Response: `{schema_version:1,descriptor_b64url:String,producer_signature:String,producer:ProducerIdentityResponse}`. Signed descriptor is exactly Access `ProductCalendarSourcePreview`; its operation is `day_calendar_source_preview`. Its nested `source` is `ProductCalendarSourceClaims`, using the supplied local revision only as an echo and the real Go provider revision/authority/identity generation. It contains actual configured physical resources, never inferred selected-as-complete catalog choices. Preview TTL is at most 30 seconds. Verify producer signature/pin/current Gateway binding before adapting it to ProductSourceObservation.
2. `admit` request: `{schema_version:1,claims:ProductCalendarClaims,expires_at_unix_ms:i64}`. The requested expiry cap is the retained permit expiry. Go caps its challenge to min(now+30 seconds, requested cap), validates every actual source/provider field and bounds, and generates the actual challenge ID/nonce/key. Response: `{schema_version:1,challenge_b64url:String,producer_signature:String,producer:ProducerIdentityResponse}`. Decoded signed bytes are exactly `ProductCalendarChallenge::Admission`.
3. `read` request: the existing closed `{schema_version:1,proof:{challenge_id,key_id,signature}}` shape. Response is the same challenge envelope as admit, with exactly `ProductCalendarChallenge::Release` binding the consumed admission and SHA-256 of the staged complete page bytes. Rust validates the retained permit/lease and signs this exact release only after checking its independent claims.
4. `release` request: the same existing proof shape. Response: `{schema_version:1,page:CalendarProductPage}`. `CalendarProductPage` and its closed nested outcome are now serde types in Context `ports/calendar_product.rs`; use every field exactly. Validate response bytes against the previously signed staged-result digest before normalization. Do not reconstruct digest bytes from a differently serialized JSON value.

`ProducerIdentityResponse` is the existing exact object `{schema_version,instance_id,execution_owner,audience,key_id,public_key,fingerprint}`. Operation/purpose/result tags are only inside signed claims, so no unsigned duplicate tag can override them. Product proofs forbid grant/consumer; assistant parsers reject product operation tags. Source preview authorizes no read.

`claims.credential_generation` is the local Rust secure-store generation, not Go issuer.Generation. Go echoes this nonzero Rust-bound value (as it does source.local_revision) and independently validates its actual principal/issuer activation and enrollment_id. Rust compares the exact retained credential generation. `gateway_runtime_generation` is another, local in-process lease epoch and is not on this wire. These three generations must never substitute for one another.

The query SHA-256 is over `serde_json::to_vec(ProductCalendarPageQuery)` field order exactly: calendar_id, range_start_unix_ms, range_end_unix_ms, cursor, limit. Rust sends those exact bytes as the nested query. Go preserves that nested raw JSON for the admission digest, strictly decodes it, and retains its parsed meaning; do not substitute Go's HTML-escaped reserialization for the digest. Rust independently recomputes the canonical typed query digest before signing. DateTime record values are RFC3339 UTC; all-day dates are YYYY-MM-DD. Tagged record schedules are `kind:timed` with starts_at/ends_at/timezone or `kind:all_day` with start_date/end_date_exclusive. External revision is `kind:provider_opaque,value:String` or `kind:observation_fingerprint,sha256:lowercase_hex_64`. All other page times are signed Unix milliseconds.

Complete/More pages contain `records`; More additionally requires nonempty cursor. Failed contains only a closed `CalendarFailure` reason. The cursor is an authenticated/server-stored Go continuation bound to read/source/account/resource/query generations and remaining budget, never a URL. Each page covers one exact physical calendar. Count repeated cursors/IDs, reject duplicate conflicting event IDs, enforce page and total ceilings, and produce Complete only after terminal coverage. A failed/incomplete resource discards its replacement records and returns Failed for that resource. No missing resource result or silent inventory truncation is allowed. Do not use the lossy assistant `calendar.timeline` projection as mirror data.

`CalendarProductReadResult.binding` uses SHA-256 and length of the exact normalized `serde_json::to_vec(&batches)` bytes, sums successful records, retains exact SourceExpectation/read ID, and sets observation/expiry within the retained permit. Context independently verifies these fields and asks Access to release. Page/result data cannot turn into a ContextDependency or model permission.
