## 1. Final boundary

AppWire is a typed intent/projection interface, not serialization of owner internals. FFI admits the verified host, validates JSON shape/encoding/size, translates owner input/output types and catches panics. Owners decide authority, workflow state, expiry, allowed actions, retries, continuation, view availability and recovery. A successful decode does not establish authority.

- Keep `floe_core_open`, `floe_core_command_v2`, `floe_core_query_v2`, `floe_core_events_v2`, `floe_protocol_version`, `floe_string_free`, `floe_core_free` with explicit allocation/lifetime semantics.
- Delete `floe_core_remote_pairing_v2` and `floe_core_remote_access_v2` with C header, Rust exports, Dart symbol lookups and all CLI/native test/tool consumers in S1.6. Pairing is ordinary Connections intent. No aliases or extra C ABI.
- Keep request ID as per-transport correlation, command ID as durable mutation identity, operation reference as observation identity, runtime epoch/cursor as observation continuity, and owner aggregate revision as CAS. None substitutes for another.
- `floe-ffi` directly depends on the public owner APIs it converts: Conversation, Connections, Access, Context, Day, Actions, Experts, Knowledge and necessary pure value contracts. App remains host/lifetime and service handles. No FFI import of Vault/provider implementations. Protocol imports only serialization and pure contracts, never domain service/adapters. Update Cargo manifests and allowed policy at the same slice boundary; delete transitive App reexports used solely to hide those dependencies.
- Preserve schema 2 AppWire and protocol 1 unless an actual same-snapshot meaning decision requires changing one; version bumps are not a compatibility mechanism. Unknown old commands/fields fail directly; no v3/next parallel path.

Safe `allowed_actions` are rendered and echoed but never replace dispatch revalidation. No binding helper invents “retry allowed” from a string error code.

`RunState::Blocked` is terminal for owner review with no fabricated model answer. Product report is `execution=blocked`, `reply=not_produced`, durable safe interaction references and retained actual settled Task/attempt references. `AppRunStateDto::Blocked` serializes as `state="blocked"`; `AppTurnExecutionDto::Blocked` as `execution="blocked"`; `AppReplyStatusDto::NotProduced` as `reply="not_produced"`. No optional `Finished` alias is used for this state. No live WaitingForUser Run is introduced. Completed still requires actual generated output where its domain invariant says so.

## 3. Internal native-host protocol

Delete ordinary product `ContextCommandDto::{Publish,PublishCalendarObservation,Revoke}` and `ContextQueryDto::Read`; feature controllers cannot publish trusted views or mirror batches. Keep OS request/response pumping only through internal `native_host.*` variants on existing command/query ABI, in new `protocol/src/dto/native_host.rs` and `ffi/src/native_host_wire.rs`. No new C ABI is needed.

AppHost registers the actual native driver/pump and issues a `NativeHostRegistrationRef` bound to admitted Person/device/runtime generation/native epoch and allowed driver kind. The native infrastructure adapter holds it; product feature interfaces do not expose registration or completion constructors. Registration is lifecycle, not a user data grant. Native completion binds registration + outstanding request ID + expected source/subject + deadline + exact result kind. Unknown/duplicate/stale/foreign completion is rejected. The host capability is not a provider credential and never appears in product settings/logs.

Native DTOs remain typed at the real platform boundary: Calendar completion, Attention completion, People completion and transformed Wellbeing completion. OS handles, physical resource IDs and before/after fingerprints belong here, never ordinary Connections/Day display DTOs. Only source-owned post-transform Health output crosses; raw/aggregate Health and Agent prompt/tool fields are excluded.

Context owns registration, outstanding request lifecycle, expected source/subject continuity, permission availability, observed-at/expiry/deadline and publication. FFI checks encoding/shape/byte bounds and invokes Context. Native timeout/disposal invalidates observation capability; it does not cancel a Run or erase an already-dispatched external Action. Type separation is an internal responsibility boundary, not a claim of isolation against a compromised process.
