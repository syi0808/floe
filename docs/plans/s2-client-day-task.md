## S3 regression handoff after integration

Exercise response loss before and after the Day mutation transaction commits. Exact retries must reuse command ID, mutation (including its original occurred_at), and original query body; a changed display-only now does not change retry identity. A correlated native error with code conflict/not_found and matching metadata.owner_code is a definite Day noncommit rejection (including successful rollback) and releases the pending UI intent. All other transport, storage, conversion and malformed-ack failures retain it; generic code matching alone is insufficient. Validate two-step capture/classification retry without a second capture.

Exercise navigation while refresh or mutation awaits, disposal while observing, the 35-second bounded metadata query, and same-operation revision/state regression. No result for a prior date may replace the current date, and observer disposal must not cancel Rust owner work. Verify explicit refresh on a second date rejoins any retained prior refresh first and then admits the requested date. Verify action Delete shows real typed blocked/unknown/collection-pending status, and task Undo forwards the current acknowledged Day revision.

Pending refresh admission IDs and original query bodies live in the app-lifetime Day gateway as well as the active observer. Recreating the Day screen after a lost admission acknowledgement must rejoin the same pending semantic query on explicit retry. A failed rollback remains Storage/uncertain and cannot release a pending mutation based on an earlier Conflict.
