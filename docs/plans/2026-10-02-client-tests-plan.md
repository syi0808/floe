## Executable scope and dependency boundaries

- `test/` mixes pure model/controller tests, Flutter widget/geometry/source-regex checks, real loopback HTTP, real diagnostic/profile filesystem operations and real FFI/Turso probes. Directory location does not imply all calls are mocked.
- `integration/` contains three Flutter test launchers, two actual subprocess host entrypoints and one exact-owned profile/key cleanup helper. `product_conversation_test.dart` builds Swift and signs a private bundle; Calendar uses the shared immutable fixture builder; pairing builds/starts a real Go loopback server. No launcher was executed.
- Native tests depend on a same-source `target/debug/libfloe_ffi.dylib`. Availability/skip behavior is inconsistent: AppWire explicitly guards macOS+dylib, Day guards dylib, Vault status opens it directly, and the integration launchers assert prerequisites. Existing skip/pass results would not prove cross-platform coverage.
- `flutter_test` is a dev dependency; its later removal must follow the aggregate repository ownership decision, not this subtree in isolation. Pretendard/Material/Lucide fonts and localization imports are production assets and remain KEEP.
- `calendar_action_execution_test.dart` imports `Gateway`, `action` and `connection` from `calendar_action_ui_test.dart`. Its `Executor` is imported by `agent_panel_test.dart` and `settings_screen_test.dart`. Delete this coupled fixture chain together only after all consumers are documented or removed.
- Shared test support composes conversation/Vault fakes, proposal/registry fixtures, owner envelope transport fakes, a real AppHost and memory-only server credentials. The direct/reverse import graph is recorded per file.
- `agent_delegation_fixture_test.dart` reads `fixtures/expert-report/delegation-v1.json`; Settings reads `server/internal/connectors/gmail/testdata/ready_snapshot.json`. Cross-language fixtures are outside this ownership scope and require aggregate consumer review.
- `FakeDayGateway`, production preview/catalog/feedback code and native adapters are imported by tests but are not test-owned files. Do not delete them by reverse association. Android cases are dormant evidence; no Android parity work is implied.

## Risks to resolve before any deletion

1. Preserve authorization, source/connection authority, native-subject and producer identity, CAS, provenance, durable pre-dispatch intent, exact key identity and uncertain external-write recovery. Record timeout, loss, release and non-replay cases before removing their assertions.
2. Differentiate explicit user Stop, `closeView`, screen disposal, lifecycle transitions, runtime closure and observer deadlines. Legacy fake paths make these look similar but assert different cancellation/storage outcomes.
3. Exact recipient-consent cards, product profile selection, historical grant-size descriptions and direct derived-Health publication are legacy implementation evidence. ADR 0034 replaces parts of that model; they must not be adopted as target requirements merely because a test asserts them.
4. Disposable cleanup is security-sensitive: validation UUID markers, non-symlink ownership checks, exact Keychain service/account deletion, verified absence, private temp roots and retained uncertain evidence need an agreed future validation story before helper removal. Deleting source never authorizes clearing any real user/provider data or key slot.
5. UI geometry, widget keys, source-regex bans and exact strings are current tests, not independent durable architecture authorities. The later evidence extraction must distinguish meaningful behavior from implementation-shape coupling.
6. Shared compiled fixture artifacts stay immutable; mutable profiles, server credentials and signed host copies stay private. Removing one client consumer does not justify removing the Rust/native fixture builder or its inputs.
