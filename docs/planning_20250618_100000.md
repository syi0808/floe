# Planning Document - 2025-06-18

## 1. Summary of Recently Completed Work (TaskAgent Calendar Linking)

This work addresses parts of the "Complete `TaskAgent` Implementation" goal, specifically focusing on calendar integration as outlined in `docs/remaining_work_plan.md` (Section 2) and `docs/implementation_plan.md` (Section 3.5.3).

*   **Implemented `task_agent/task_calendar_linker.py`:**
    *   **Purpose:** This module is responsible for linking tasks managed by `TaskAgent` to calendar events via a scheduling service/agent. It facilitates creating, retrieving (conceptually, as storage is currently in-memory), and removing these calendar links.
    *   **Key Functionalities:**
        *   `create_calendar_event_for_task`: Calculates event timings based on various inputs (start/end, start/duration, end/duration, duration only), prepares event details, and calls a client to create the event.
        *   `get_task_calendar_link`: Retrieves stored link information (currently from an in-memory dictionary `_links`).
        *   `remove_calendar_event_for_task`: Calls a client to delete a calendar event, using either a provided event ID or one fetched from internal storage.
    *   **Client Abstraction:** Introduced `BaseScheduleAgentClient` as an interface for calendar service interaction and `MockScheduleAgentClient` (based on the one in tests) as a default, usable mock. This allows for future integration with a real `ScheduleAgent` or calendar API.
    *   **Data Models:** Defines `TaskCalendarLink` (Pydantic model) to represent the link and its status. It is designed to work with task information (like ID and description) that would originate from `TaskItem` in `task_agent.task_core.py`.
*   **Unit Testing for `TaskCalendarLinker`:**
    *   The existing test file `tests/task_agent/test_task_calendar_linker.py` initially contained 10 tests.
    *   These tests were reviewed, and significant gaps were identified in coverage for client interactions, error handling, edge cases (e.g., inconsistent time parameters, naive datetimes), and stateful behavior (retrieving created links, status changes after deletion).
    *   10 new, more comprehensive tests were added, utilizing `unittest.mock.AsyncMock` for better verification of client calls and behavior.
    *   **All 20 tests for `task_calendar_linker.py` are currently passing.**

## 2. Next Steps: Integrating `TaskCalendarLinker` with `TaskAgent` and `TaskCore`

Based on the completed implementation of `TaskCalendarLinker` and reviewing `docs/remaining_work_plan.md` and `docs/project_status_summary.md`, the next logical step is to fully integrate this calendar linking capability into the `TaskAgent` and `TaskCore` modules. This directly follows the plan to "Complete `TaskAgent` Implementation."

### 2.1. Goal

Enable `TaskAgent` to create, manage, and remove calendar events associated with tasks by leveraging `TaskCalendarLinker`.

### 2.2. Key Sub-Tasks

1.  **Modify `TaskCore` (`task_agent/task_core.py`):**
    *   **Update `TaskItem`:** Ensure `linked_schedule_id: Optional[str]` is actively used.
    *   **Enhance `create_task`:**
        *   Accept optional scheduling parameters (e.g., `schedule_start_time`, `schedule_end_time`, `schedule_duration_minutes`) derived from `TaskAgent`.
        *   If scheduling parameters are provided (or inferable from `due_date_utc`), instantiate `TaskCalendarLinker`.
        *   Call `task_calendar_linker.create_calendar_event_for_task`.
        *   If successful, store the returned `calendar_event_id` in `TaskItem.linked_schedule_id`.
        *   Consider how to handle failures in calendar event creation (e.g., log an error, return a partial success, or fail the task creation).
    *   **Enhance `update_task`:**
        *   If task timing information (`due_date_utc`, or new specific scheduling fields) changes, or if a task is newly requested to be scheduled:
            *   Remove any existing linked calendar event using `TaskCalendarLinker.remove_calendar_event_for_task` if `TaskItem.linked_schedule_id` exists.
            *   Create a new calendar event using `TaskCalendarLinker.create_calendar_event_for_task` with the updated details.
            *   Update `TaskItem.linked_schedule_id`.
        *   If a task is being unscheduled, remove the linked event and clear `linked_schedule_id`.
    *   **Enhance `delete_task`:**
        *   If `TaskItem.linked_schedule_id` exists, call `TaskCalendarLinker.remove_calendar_event_for_task` to remove the associated calendar event before deleting the task from storage.

2.  **Modify `TaskAgent` (`task_agent/task_agent.py`):**
    *   **Command Parsing:**
        *   Update `_parse_common_task_attributes` or add new parsing logic to extract scheduling-specific parameters from user commands (e.g., "add task 'Team meeting' due tomorrow schedule for 2 PM for 1 hour", "schedule task 'Project work' on Friday afternoon"). This might involve coordination with `task_parser.py` if more complex NLP-based extraction is needed for these schedule details.
        *   These parameters will then be passed to `task_core` functions.
    *   **Update Handler Methods (`_handle_create_task`, `_handle_update_task`, `_handle_delete_task`):**
        *   Pass the newly parsed scheduling parameters to the corresponding `task_core` functions.
        *   Update response messages to inform the user about calendar event creation/deletion status.
    *   **Instantiate `TaskCalendarLinker`:** Decide where `TaskCalendarLinker` (and its `schedule_agent_client`) will be instantiated. It might be passed to `TaskCore` functions, or `TaskCore` might instantiate it internally. For better testability and dependency management, passing it (or the client) might be preferable.

3.  **Unit Testing for `TaskCore` and `TaskAgent`:**
    *   Add new unit tests and update existing ones in `tests/task_agent/test_task_core.py` and `tests/task_agent/test_task_agent.py`.
    *   These tests must mock `TaskCalendarLinker` (or its client) to verify:
        *   That `create_calendar_event_for_task` and `remove_calendar_event_for_task` are called appropriately by `TaskCore` functions.
        *   That `TaskItem.linked_schedule_id` is correctly set and cleared.
        *   That `TaskAgent` correctly parses scheduling commands and provides appropriate feedback.

### 2.3. Considerations

*   **Error Handling:** Robustly handle errors from `TaskCalendarLinker` (e.g., if the calendar service is unavailable). Decide if task operations should fail or proceed with a warning if calendar linking fails.
*   **Configuration of `ScheduleAgentClient`:** The `TaskCalendarLinker` currently defaults to a `MockScheduleAgentClient`. A mechanism will be needed to inject a real client implementation when moving towards actual `ScheduleAgent` integration or direct calendar API calls. This might involve environment configuration or a factory pattern. For now, continuing with the mock is acceptable for initial integration.
*   **User Experience:** How will the agent communicate success/failure of calendar linking to the user? This needs to be reflected in the `AgentResponse` messages.

This plan sets the stage for making tasks schedule-aware and directly actionable on a user's calendar, a core piece of functionality for the Floe AI Assistant.
