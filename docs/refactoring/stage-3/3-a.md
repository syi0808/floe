# 3-A — Remaining Root and Domain Caller Convergence

**Status: ready**

**Planning baseline:** `170770d314bd0b6bef0a6370cc367222fe9399bb`  
**Code baseline:** `39263a1339d0519b78a20680c0eea73506ff6d6f` (`2-F`; the planning commit after it changed docs only)

This document is the authoritative execution plan for 3-A.

## Goal

Converge every live production model-execution caller left outside the Stage 2 General Conversation cutover onto **one Inference-owned provider/route/attempt/usage path** while preserving each domain's own reasoning semantics.

The reviewed production debt is exactly three caller clusters:

1. delegated built-in Experts;
2. Schedule / Calendar;
3. Knowledge Learner.

Before those callers move, canonical Foundation inference must use the already-existing bundled native model instead of returning `LocalModelUnavailable`.

3-A changes model-execution ownership. It does not reopen the Stage 2 Manager runtime and it does not start AppHost/FFI/Flutter product-boundary work.

## Frozen foundation

Do not redesign or weaken:

- Conversation Run/transcript/continuation/finalization;
- Agent Engine validated-batch durability and cursor replay;
- exact Tool invocation identity;
- delegation request digest / execution-context binding;
- TaskCoordinator TaskId / InvocationKey / single settlement;
- Context dependency coverage and history reauthorization;
- ContextToolService;
- Access exact-recipient admit → consume → post-response revalidation;
- Inference attempt settlement and Auto/explicit fallback rules;
- `ExecutionScope` parent → child cancellation direction;
- durable pre-dispatch intent;
- uncertain external-write recovery.

If a remaining caller does not fit the canonical owner contracts, adapt the caller or add the narrow owner-facing contract required by that caller. Do not create a second model runtime.

## Fixed 3-A design

### One Inference execution implementation

`InferenceService` remains the only production owner of:

- profile observation and candidate selection;
- execution-location constraint evaluation;
- Access model-dispatch admit/consume/revalidate;
- provider handoff;
- attempt identity;
- model budget settlement;
- transport fallback;
- trustworthy usage accounting.

The current `ModelPort` implementation is root-specific because it pins `CANONICAL_MODEL_PURPOSE` and `CANONICAL_MODEL_CONSUMER`. Preserve that root invariant.

Extract/generalize the body of `InferenceService::generate_inner` into one Inference-owned execution entry, then keep `impl ModelPort for InferenceService` as the Conversation-root adapter.

Use an owner-level constraint shaped like:

~~~rust
pub enum InferenceExecutionConstraint {
    Any,
    DeviceOnly,
    RemoteOnly,
}
~~~

and one shared execution entry, for example:

~~~rust
InferenceService::execute(
    ModelRequest,
    &ExecutionScope,
    InferenceExecutionConstraint,
) -> Result<ModelResponse, AgentFailure>
~~~

Exact naming/visibility may vary if a narrower Inference trait is cleaner, but there must be only one implementation of candidate planning, Access fencing, attempt lifecycle, fallback and settlement.

Do not introduce `InferenceServiceV2`, `DomainInferenceService`, a second router loop or another usage ledger.

### Domain callers express constraints, not routes

Semantic mapping:

~~~text
General Conversation       → Any
Focus/device-only Expert   → DeviceOnly
remote-only built-in       → RemoteOnly
Schedule OnDevice          → DeviceOnly
Schedule ConversationRoute → Any
Knowledge Learner          → DeviceOnly
~~~

A caller must not construct `RemoteRoute`, `candidate_route`, `FoundationModelRunner`, `ServerModelRunner`, endpoint/token or a chosen provider transport.

Inference selects a profile satisfying request purpose/consumer plus the execution constraint.

### Preserve purpose/consumer meaning

Only the root `ModelPort` adapter pins `conversation.root`.

The shared path accepts domain purpose/consumer. Knowledge retains:

~~~text
purpose  = governed-memory-review
consumer = knowledge.learner
~~~

Do not label every domain call `conversation.root` simply to reuse the root profile.

Provider adapters must not import Expert or Knowledge crates. If domain-specific profile scoping is needed, implement it in Inference/composition over non-secret profile facts.

### ExecutionScope is the sole model budget owner

Delegated endpoints already receive an `ExecutionScope` from TaskCoordinator.

Expert/Schedule calls derive bounded child scopes from that parent. Their max tokens/cost/deadline remain domain limits, but model attempts settle against the shared execution ledger.

The Learner is background work, not a child of the foreground turn. Convert `LearnerBudget` into a background root `ExecutionScope`; Inference owns attempts inside it.

Do not retain detached `UsageLedger` model accounting after cutover.

### Expert placement is intent

Current provider preselection leaks through:

- `ExpertModel::placement()`;
- `BuiltinExpertHost::server_model()`;
- `BuiltinExpertHost::device_model()`;
- `Model::expert_eligibility()`.

Replace this with an Expert-owned requirement such as:

~~~rust
pub enum ExpertModelRequirement {
    Any,
    DeviceOnly,
    RemoteOnly,
}
~~~

carried by `ExpertModelCall` / `ExpertReasoningStep` or an equivalent contract.

Experts may state what execution class they require; they must not inspect which provider Inference chose.

### Reuse Context projection

Use the existing Context-owned `ContextProjectionInput` and `assemble_context_projection`.

Extend projection roles only as narrowly as needed for Expert/Learner use. Map Expert transcript to `ModelConversation`, Expert capabilities to canonical `AllowedCatalog`, and preserve exact source dependency coverage.

Do not recreate the old Conversation `ModelRequest::context_envelope()` path in App.

Do not put route, endpoint, credential, recipient or transfer-consent policy into the projection. Access remains the model-recipient authority after Inference selects a candidate.

Source-backed Expert input must not become `DependencyCoverage::Independent`.
