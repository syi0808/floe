# 3-E — Outer Compatibility Deletion

**Status: pending · deletion classes fixed from Stage 3 baseline review**

## Goal

Delete the compatibility surfaces whose real production callers were moved in 3-A through 3-D.

3-E is deletion and fallout cleanup, not another architecture redesign.

## Deletion rule

For every target:

1. prove real production caller count is zero;
2. distinguish tests/examples/tools from product callers;
3. delete the old implementation and its forwarding exports/conversion/tests;
4. do not replace it with a renamed wrapper;
5. do not delete an unrelated connection-domain value merely because its name contains `remote`, `route`, `legacy` or `v2`.

## E1 — model/domain runtime compatibility after 3-A

Revalidate and delete caller-zero legacy execution surfaces such as:

- delegated Expert `expert_compat::Model` path;
- `TransportModelRunner`;
- `generate_with_recovery`;
- old `ModelRunner` / `ModelRequest` / `ModelResponse` surfaces;
- legacy `AgentRuntime` / `CapabilityHost` used only by migrated domain/fixture callers;
- `CalendarTurn` / `CalendarAgentTurnRequest`;
- `run_calendar_agent_turn` and other Schedule wrappers;
- Learner raw `ModelTransport` adapters;
- `FoundationModelRunner` / `ServerModelRunner` compatibility constructors if no non-test production caller remains;
- `ModelRouteConfig`, `candidate_route`, `RemoteModelConnection` only when their exact callers are gone.

Do not delete any Stage 2 canonical Inference/Access/Engine contract.

## E2 — product route compatibility after 3-C/3-D

Expected deletion candidates include:

- `AgentRemoteRouteDto`;
- `RemoteTurnRoute` if no genuine connection-domain caller remains;
- old FFI remote-route conversion;
- Flutter `authorityRoute`/pairing route bundles replaced by final connection intent;
- deprecated `AgentConversationTurnRequestDto.remote_route`;
- duplicate AgentVault ConversationTurn wire;
- route helpers whose only role was translating Inference route types into Connections/Access identity.

Preserve stable connection/pairing identity types owned by Connections/Access.

## E3 — AppHost/FFI compatibility

After caller migration, revalidate:

- `FloeHandle.services()`;
- `AppHost::legacy_services()`;
- `AppHost::legacy(...)` production callers;
- old worker-shaped ABI operations;
- old fixture C ABI entry points;
- temporary protocol fields and generated/client bindings.

Delete only the caller-zero subset.

Tests that need a non-product host should use an explicit test helper rather than keeping a production “legacy” constructor solely for tests.

## E4 — AgentFixture compatibility

Apply the 3-D decision:

- if moved to dev/test tooling, delete production fixture protocol/FFI/Flutter surfaces;
- if product behavior migrated to canonical Conversation, delete the old fixture runtime after final caller cutover.

Do not leave both old fixture model execution and canonical Conversation as permanent product paths.

## Static gates

At closure, search for the concrete deleted symbols and for classes of pre-refactor topology:

- product DTO bearer/base URL/model route fields;
- production `ModelTransportRequest` construction outside Inference/provider implementation;
- production `TransportModelRunner`/legacy runtime callers;
- App conversion from `floe_inference::RoutePairing` to Connections/Access identities;
- duplicate Conversation turn wire;
- old AgentVault fixture/worker operations declared deleted by this slice.

Expected results must distinguish provider-internal implementation and tests from product callers.

## Acceptance

3-E is complete when:

- every deleted type/function had zero production callers at deletion time;
- no renamed compatibility wrapper restores the same architecture;
- final Flutter/generated/protocol bindings contain no stale route/bearer fields;
- no fallback restores pre-Stage-2 model routing;
- real connection/pairing domain intent remains represented by Connections/Access contracts;
- canonical Foundation/provider internals needed by Inference remain intact;
- focused and workspace checks pass;
- architecture checker reports zero errors/warnings;
- `git diff --check` is clean.

On completion, mark 3-E complete/frozen, update the Stage 3 checkpoint to 3-F and stop.
