# Evidence tiers

Every final claim in the Agent report must name its evidence tier.

## Tier A — final product boundary

Real final product code crossing the final boundary.

Examples:

- Flutter AppRuntime → real floe-ffi dylib → command_v2/query_v2/events_v2;
- Flutter strict pairing → real Go server;
- final macOS packaged dylibs loaded from the app bundle;
- product Conversation run observed through the Flutter read path.

Tier A proves the final outer composition, not every fault permutation.

## Tier B — canonical deterministic owner/runtime

Rust/App/Flutter tests that exercise the same canonical owners and durable state without pretending to be a real external platform.

Use Tier B for fault timing that is unsafe or nondeterministic at the UI boundary:

- post-response revocation;
- durable batch crash points;
- Tool/Delegation result-before-cursor;
- cross-run continuation takeover;
- exact Task replay;
- model usage settlement;
- key-loss reconciliation;
- response-loss external-write lookup;
- Learner retry/idempotency.

## Tier C — real platform/provider

Actual OS/provider/server evidence:

- bundled FoundationModels availability/generation on supported macOS;
- real Keychain Vault lifecycle;
- EventKit permission/read behavior;
- controlled real EventKit write/reconciliation when explicitly authorized;
- real Go server pairing/current saved-connection authorization/revocation;

Do not label fixture/mock evidence Tier C.
