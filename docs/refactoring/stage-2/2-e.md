# 2-E — Internal Public-Surface Closure

**Status: ready**

**Code baseline reviewed:** a8b21b6651f2921ac53142394658d4d3d96c6596

This document is the authoritative execution plan for 2-E.

2-D is complete/frozen. Do not reopen 2-B through 2-D, and do not pull Stage 3-A Expert/domain convergence or Stage 3 FFI/product-boundary deletion into this slice.

## Goal

Make the Stage 2 crate roots express real owner APIs instead of exposing:

- internal module topology;
- migration-only re-exports of another owner's types;
- App-only composition helpers;
- test/convenience paths that external production code does not need.

2-E is a **visibility and ownership-surface closure**, not a behavior cutover.

At exit:

~~~text
external Rust caller
  → owner crate root API
  → owned contract/service/port

not

external Rust caller
  → owner::application/...
  → owner::ports/...
  → owner::turn/...
  → App composition helper
  → migration alias of another owner's type
~~~

The General Conversation runtime, delegated Expert/Schedule compatibility, FFI wire behavior, route semantics, authority checks, recovery identity and provider transport behavior must remain semantically unchanged.

## Fixed classification rule

Before changing visibility, classify each symbol by its current caller.

| Surface | 2-E action |
| --- | --- |
| canonical owner API used cross-crate | keep public at the owner crate root |
| internal module path when the same value is already available from the crate root | make module private and move callers to the root |
| another owner's type re-exported as migration convenience | move callers to the real owner and remove the alias |
| App-only composition/helper with no external product caller | remove root export and reduce to crate-private |
| delegated Expert/Schedule behavior still used in production | keep until Stage 3-A |
| FFI/Flutter/native/server or remote-authority outer caller still exists | keep until Stage 3 |
| secret-bearing legacy compatibility type with an exact deferred caller | keep only for that caller; do not relocate it for grep cleanliness |

A name containing `legacy`, `compat`, `internal`, `route` or `transport` is not sufficient evidence for reducing visibility.

### Inference

Current root exposes canonical contracts plus compatibility and also exposes `pub mod ports`.

The reviewed call graph shows:

- canonical provider/transport types are already re-exported from `floe_inference::*`;
- the remaining direct `floe_inference::ports::...` caller is a provider-adapter test and can import the root API;

  attempt values, model-provider/transport contracts and other current cross-crate owner values remain public.

The following secret-bearing compatibility values are **not** automatically deleted or relocated in 2-E:

- `SavedServerConnection`;
- `RemoteModelConnection`;
- `RemoteRoute`;
- `RoutePairing`;
- `ModelRouteConfig`;
- `candidate_route`.

They still serve delegated Expert/domain or outer remote-authority/pairing callers. Stage 2's secret-boundary invariant applies to the **canonical model-dispatch public contract**: `InferenceService`, model profiles, canonical requests and prepared transports must expose no bearer/base URL. Do not distort live Stage 3 compatibility merely to make a repository-wide grep for `bearer` empty.

### Context

Current root has complete owner re-exports but also exposes:

~~~rust

~~~

External direct application-path callers are limited to the Day context-view helpers:

- `task_context_view`;

Promote those two functions to the Context crate root, update callers, then hide the `application` and `ports` module topology. All other existing root Context contracts remain available.

### Access

Current root already re-exports the authority/admission/grant/fence contracts required cross-crate, while also exposing:

~~~rust

pub mod ports;
~~~

No reviewed external caller requires those nested module paths. Hide both module trees and preserve the root public API.

### App

The App crate is a product/composition boundary, so 2-E must distinguish internal composition from Stage 3 outer callers.

Safe internal closures on the reviewed baseline:

- `pub mod local_context` → private module; keep required root types;
- `pub mod turn_request` → private module; keep `ConversationTurnRequest` and `RemoteTurnRoute` root exports;
- `pub mod worker` → private module; keep the existing worker command/result root exports;
- remove the root export of `HostInferenceRoutes` and reduce the type itself to crate-private;
- remove the App root re-export of `PublishedCalendarObservation`; App already consumes the Context owner value directly;
- remove the App root export of `local_identity_for_database` and make/use it as an internal bootstrap helper if current caller revalidation still shows only App composition.

Do **not** close these yet:

- `pub mod agent_run`: FFI currently calls `floe_app::agent_run::run`;
- `pub mod events`: FFI currently imports `events::{EventPayload, EventRead, RunEventRecord}`;
- `RemoteTurnRoute`, `RemoteRoute`, `RoutePairing`, `AgentOutcome` and current worker/root product values used by FFI;
- AppHost/FFI compatibility constructors and `legacy_services()`;
- protocol/Flutter/native/server DTOs.

Those are Stage 3 product-boundary callers.
