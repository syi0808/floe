# 2-D — Internal Compatibility Cleanup

**Status: complete · frozen**

**Code baseline reviewed:** 065910932ee99c200e7b87c0d334cd431568c4fe

This document is the authoritative execution plan for 2-D.

2-C is complete/frozen. Do not reopen 2-B/2-C or pull Stage 3-A Expert/domain convergence forward merely because a symbol looks legacy.

## Goal

Delete internal compatibility surfaces whose production caller count is now zero, while preserving compatibility that still serves an intentionally deferred production caller.

2-D is therefore:

~~~text
zero-production-caller compatibility deletion
+ fallout cleanup caused by those deletions
~~~

It is not:

~~~text
delete every old Conversation / ModelTransport symbol
canonicalize delegated Expert/Schedule runtime
outer FFI/Flutter compatibility cleanup
public-API minimization for its own sake
~~~

At 2-D exit, the known caller-less bridge leaves below are gone, no renamed equivalent replaces them, all still-live Stage 3-A/Stage 3 compatibility remains intact, and Stage 2 can move to 2-E public-surface closure.

## Fixed scope rule

Before deleting a compatibility symbol, classify it by actual current caller:

| Class | 2-D action |
| --- | --- |
| production caller = 0, compatibility-only | delete in 2-D |
| delegated Expert/Schedule production caller exists | keep for Stage 3-A |
| outer FFI/Flutter/remote-authority product boundary caller exists | keep for Stage 3 |
| only visibility/re-export ergonomics remain after behavior is retained | leave to 2-E unless deleting the underlying dead symbol makes the export disappear naturally |

Do not use names such as `legacy`, `compat`, `old` or `RemoteRoute` as deletion evidence. Caller ownership is the evidence.
