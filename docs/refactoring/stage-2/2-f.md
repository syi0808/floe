## Fixed blocker classification

When validation finds something, classify it before editing.

### Stage 2 blocker — fix before closure

Only a direct regression of the canonical internal runtime qualifies, including:

- General Conversation production root no longer uses the canonical Model/Tool/Delegation owners;
- authorization/exact-recipient/revocation fence bypass;
- durable validated pending work can be lost and re-planned;
- Tool/Task replay identity or delegation request-context binding can change under replay/recovery;
- model usage can resurrect, double-settle or disappear across fallback/recovery;
- canonical Context projection loses required provenance/coverage/freshness reauthorization;
- canonical public model/projection/access handoff exposes raw credentials/endpoint;
- 2-C staging/run-id delegation state reappears;
- a Stage 2 public-surface closure from 2-E has regressed;
- required workspace/architecture gates fail because of Stage 2 code.

### Stage 3 debt — not a 2-F blocker

Do not fix in 2-F:

- delegated Expert/Schedule legacy model runtime still using
  `AgentRuntime`, `ModelRunner`, `CapabilityHost`,
  `generate_with_recovery`, `TransportModelRunner` or `CalendarTurn`;
- `expert_compat.rs` and Schedule/domain canonicalization;
- AppHost/FFI/Flutter/native/server product-boundary convergence;
- `RemoteTurnRoute`, `AgentRemoteRouteDto`, outer route conversion or
  `AppHost::legacy_services()`;
- `SavedServerConnection`, `RemoteRoute`, `RoutePairing`,
  `RemoteModelConnection`, `ModelRouteConfig` or `candidate_route`
  while their exact deferred callers remain;
- canonical Foundation transport → real native Foundation Models wiring;
- final Apple/product end-to-end evidence.

Those belong to Stage 3, primarily 3-A through 3-F.

### Non-blocking cleanup / harness issue

Do not broaden 2-F for:

- dead-code/naming/visibility cleanup not violating a 2-E gate;
- pre-existing warnings unchanged from the 2-F baseline;
- unrelated test-fixture ergonomics;
- the known calendar mock-socket load `WouldBlock` flake when it is baseline-reproducible and passes alone.

No new compatibility wrapper may be added to silence a validation failure.
