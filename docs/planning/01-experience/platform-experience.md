# Platform Experience

> Status: Accepted direction

## 원칙

**Feature parity가 아니라 Experience parity를 목표로 한다.**

각 OS의 제한과 강점을 무시한 채 동일 UI/interaction을 복제하지 않는다.

## macOS

역할:

- full Day Canvas
- 계획/정리
- desktop context
- ambient voice
- 긴 대화
- 회의/전사
- local compute

## Windows

역할:

- macOS와 동급의 desktop surface
- ambient voice
- global invocation
- Day Canvas
- transcription
- local compute

## iOS

역할:

- 이동 중 Floe
- 빠른 capture
- Back Tap / system intent 기반 호출
- notifications
- location/context
- HealthKit source

## Android

역할:

- 이동 중 Floe
- assistant-level integration
- quick system invocation
- notifications/context
- Health Connect source

## Watch

필수 UX surface로 보지 않는다.

지원 시:

- health
- glanceable information
- notification actions

에 집중한다.

## 부모님 사용 시나리오

기본 제품은 기술 지식 없이:

```text
Install
↓
Sign in
↓
Connect
↓
Use
```

수준이어야 한다.

Self-hosting이나 모델/provider 세부사항은 기본 UX에서 노출하지 않는다.
