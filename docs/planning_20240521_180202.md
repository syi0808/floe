# Floe Project Plan Update - 2024-05-21 18:02:02 UTC

This document summarizes the significant work completed on calendar integration and outlines potential next steps for the project.

## Summary of Calendar Integration Work Completed

A robust calendar integration framework has been implemented, allowing Floe to interact with different calendar backends. Key achievements include:

1.  **Research & Design**:
    *   Researched Google Calendar API (Python client library, OAuth 2.0 authentication).
    *   Researched Apple Calendar automation on macOS (via AppleScript and `osascript`).

2.  **`CalendarAdapter` Protocol**:
    *   Defined a `CalendarAdapter` protocol in `orchestrator_agent/calendar_adapters/base_adapter.py`.
    *   This protocol specifies a standard interface (`connect`, `create_event`, `get_event`, `update_event`, `delete_event`, `list_events`) for all calendar adapters, ensuring consistency.
    *   Marked with `@runtime_checkable` for runtime instance checks.

3.  **`GoogleCalendarAdapter` Implementation**:
    *   Developed `orchestrator_agent/calendar_adapters/google_calendar_adapter.py`.
    *   Handles OAuth 2.0 flow for authentication (using `credentials.json` and `token.json`).
    *   Implements all methods of the `CalendarAdapter` protocol for Google Calendar.
    *   Translates between Floe's internal `CalendarEvent` model and Google Calendar API's event structure.
    *   Stores and retrieves Floe-specific event and task IDs using Google Calendar's extended properties (`privateExtendedProperty`).

4.  **`AppleCalendarAdapter` Implementation**:
    *   Developed `orchestrator_agent/calendar_adapters/apple_calendar_adapter.py`.
    *   Interacts with Apple Calendar on macOS by generating and executing AppleScript commands via `subprocess.run` and `osascript`.
    *   Implements all `CalendarAdapter` protocol methods for Apple Calendar.
    *   Embeds and extracts Floe-specific event and task IDs within the event's description field using a defined format (`KEY::VALUE`).
    *   Includes helper functions for AppleScript string escaping, date conversions, and parsing AppleScript output.

5.  **Refactoring of `task_agent/task_calendar_linker.py`**:
    *   The `TaskCalendarLinker` class now utilizes the `CalendarAdapter` protocol (dependency injection). This decouples the linker from specific calendar implementations.
    *   The `create_calendar_event_from_task` utility function was updated to generate unique UUIDs for new `CalendarEvent` instances by default, or use a provided `base_event_id` for updates.
    *   `CalendarEvent.task_id_ref` field was made optional.

6.  **Adapter Factory**:
    *   Implemented `get_calendar_adapter()` in `orchestrator_agent/calendar_adapters/__init__.py`.
    *   This factory function selects and instantiates the appropriate calendar adapter (`GoogleCalendarAdapter` or `AppleCalendarAdapter`) based on the `CALENDAR_BACKEND` environment variable or a direct argument. It includes a platform check for the Apple adapter.

7.  **Comprehensive Unit Tests**:
    *   Developed extensive unit tests for `GoogleCalendarAdapter`, mocking Google API services, OAuth flow, and handling API errors.
    *   Developed unit tests for `AppleCalendarAdapter`, mocking `subprocess.run` to simulate `osascript` behavior and different AppleScript outcomes.
    *   Updated and added tests for `TaskCalendarLinker`, using a mocked `CalendarAdapter` to verify its logic.
    *   Created unit tests for the `get_calendar_adapter` factory function, covering various scenarios.
    *   All implemented unit tests (55 in total for these components) are passing.

## Potential Next Steps / Future Enhancements

The following areas can be considered for future development sessions:

**A. Immediate Task Agent Integration (High Priority):**
    *   As per `docs/planning_20240521_155658.md`, the primary next step is to **integrate the refactored `TaskCalendarLinker` (with its new adapter system) into `task_agent/task_core.py` or `task_agent/task_agent.py`**. This will enable tasks managed by the `TaskAgent` to be actually linked to external calendars.

**B. Calendar System Enhancements:**
    1.  **User Configuration for Calendar Target**: Allow users to specify target calendar names/IDs (e.g., "Work", "Personal" instead of just "primary" or "Calendar") through configuration files or environment variables, to be used by the adapters.
    2.  **Real-world Testing & User Feedback**: Conduct thorough testing in real Google Calendar and Apple Calendar environments. Gather user feedback on the OAuth flow for Google, AppleScript permissions, and overall usability.
    3.  **Credential Management (Google Calendar)**:
        *   Provide clear instructions for users to obtain `credentials.json`.
        *   Implement more secure storage for `token.json` rather than just a local file in the root directory, if required by security considerations.
        *   Allow configuration of `credentials.json` and `token.json` paths.
    4.  **Apple Calendar - Calendar Selection**: Implement a function in `AppleCalendarAdapter` to list available calendars on the user's system, allowing the user or system to select a specific calendar if the default is not desired.
    5.  **Error Handling & User Messaging**: Improve user-facing error messages for calendar interaction issues (e.g., permissions denied, API rate limits, specific HTTP errors, AppleScript failures).
    6.  **Synchronization Logic**: Design and implement logic for more complex synchronization scenarios (e.g., bi-directional sync, handling updates made directly in the external calendar). Current implementation is primarily app-to-calendar.
    7.  **Support for All-Day Events**: Explicitly test and, if necessary, enhance handling for all-day events in both adapters and the `CalendarEvent` model.
    8.  **Recurring Events**: Investigate and implement support for creating, reading, updating, and deleting recurring events. This is a complex feature with significant differences between calendar systems.
    9.  **Timezone Handling**: Conduct a thorough review and implement more sophisticated timezone management across all adapters and `CalendarEvent` to ensure consistency, especially for users who travel or work across multiple timezones.
    10. **Address Pydantic V1 Deprecation Warnings**: As noted in previous plans and test outputs, update Pydantic models to V2 style (e.g. `@field_validator`).

**C. Broader Application Development:**
    1.  **UI Integration**: Design and implement how the user will interact with calendar linking features, select calendar backends, and manage calendar connections from within the Floe application interface.
    2.  **Refine `task_core.py` Functionality**: Continue work on `task_agent/task_core.py` as per `docs/planning_20240521_155658.md` if its core features (CRUD, priority, etc.) are not yet complete.

The immediate focus after this calendar integration work should likely be on integrating these capabilities into the `TaskAgent` (Item A). Following that, addressing Pydantic deprecations (part of Item B.10) and then further calendar enhancements or other agent development can be prioritized.
